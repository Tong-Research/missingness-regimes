# B7 — per-pattern adaptive shrinkage — pre-registered 2026-08-27 11:12, BEFORE the run

## What is being tested

Paper C found that interpolating a site's model toward the federation's, at a weight chosen on
held-out *local* data, is the only policy never harmful on any pool — best mean and best worst
case. Missingness patterns have the same shape as sites: disjoint groups of records, each with its
own conditional distribution, each usually too small to fit alone. The port has never been run.

Four arms, all sharing `(seed, fold)` splits so every contrast is paired:

| arm | what it may use |
|---|---|
| `pooled` | one model on all training rows — the frozen `mean_indicator` design |
| `local` | each group's own model where support $\ge 30$, pooled elsewhere ($\lambda = 0$) |
| `blend_cv` | per-group $\lambda$ chosen on an inner split of that group's own training rows |
| `blend_oracle` | per-group $\lambda$ chosen on the **outer test rows** — not attainable |

This composes with the winner rather than competing with it: `pooled` is `mean_indicator`, the
baseline this method family currently loses to.

## Why the oracle arm is the decisive one

$\lambda = 1$ recovers `pooled` exactly, so `blend_oracle` $\ge$ `pooled` is **arithmetic, not
evidence**. Its *margin* is the finding. If the oracle — allowed to pick each group's weight using
the test labels themselves — cannot clear the $0.002$ floor over `pooled`, then no attainable
selection rule can, and how noisy `blend_cv` is stops mattering. That is the oracle-ceiling logic
this project already relies on, applied one level down.

## The null

Records are regrouped at random, preserving the group **size distribution exactly** (a permutation
of the real ids, so the multiset of group sizes is identical). Values and outcomes are untouched.
The question it asks is the only one that matters: do *real* patterns beat *random* groups of the
same sizes? A method that gains as much from random groups has found group-size structure, not
missingness structure.

Four selftest guards, each confirmed to fail under a deliberate mutation: `pooled` reproduces the
frozen `mean_indicator_lr`; the oracle is weakly above `pooled`; the null regroups; the null
preserves group sizes. A fifth — that no two arms are the same function — caught this design's own
first test being vacuous, where the synthetic data had 1024 patterns for 2000 rows and every arm
silently fell back to `pooled`.

## Predictions

1. **`blend_oracle` beats `pooled` by less than $0.002$** on both dev cohorts. The oracle ceiling
   already says the attainable gain over the whole pattern lattice is $+0.0066$ against a permuted
   null of $+0.0111$; a per-group weight is a strictly smaller search space than choosing the
   pattern set outright.
2. **`blend_cv` does not beat `pooled`** by the floor. Group-scale support is 30–300 records at
   1–10% prevalence, so an inner AUPRC estimate is chosen from a handful of positives. Paper C's
   sites were far larger.
3. **`local` is clearly worse than `pooled`** on both cohorts — this is Paper 1's central result
   restated, and if it fails the whole paper is in question.
4. **`blend_oracle`'s gain under the null is no smaller than its real gain.** Random groups of the
   same sizes should buy the oracle just as much, because what the oracle exploits at this scale
   is overfitting room, not structure.

## Withdrawal conditions

- **(a) If prediction 1 fails** — the oracle clears the floor on both cohorts *and* beats its own
  null — there is real per-pattern structure that Paper 1's framing misses. That is a finding, and
  it means `blend_cv` deserves a proper attempt rather than a single inner split.
- **(b) If prediction 3 fails** and `local` beats `pooled`, stop: something is wrong with the
  harness, because that contradicts every result this project has produced. Do not report it as a
  discovery before finding the bug.
- **(c) If prediction 4 fails** — the real grouping beats the null grouping by $\ge 0.002$ — then
  missingness structure is carrying something that group size alone does not, which is the
  strongest possible result for the method family and must be replicated before being believed.

## Scope

Development cohorts colorectal and lung only; ovarian and prostate refused in code. 5 seeds x 5
folds, 40,000-record subsample, baseline features, `MIN_SUPPORT = 30`, Paper C's $\lambda$ grid
unchanged. Levels are not comparable to the paper's main table and are not reported as such.

## Amendment — 2026-08-27 11:36, after the first run was stopped and before the re-run

The original text above is left unedited. It contains an error, and the error is the point.

**What was wrong.** "$\lambda = 1$ recovers `pooled` exactly, so `blend_oracle` $\ge$ `pooled` is
arithmetic, not evidence." False. $\lambda = 1$ *everywhere simultaneously* recovers `pooled`, but
a per-group argmax on each group's own AUPRC is a different objective from the global AUPRC being
reported. On colorectal the first run's oracle was better within groups in 30, worse in 0, tied in
40 — and globally **worse**, $0.1213$ against $0.1309$. Result 143 records this.

**What changed.** `blend_oracle` now ascends on the global AUPRC it is scored on, initialised at
$\lambda = 1$ for every group so it starts exactly at `pooled` and accepts only strict
improvements. It is a ceiling by construction rather than by assumption, and the invariant now
holds on the real cohort where the old one failed ($+0.0203$ on the fold that broke it).

**What this does to the predictions.** Prediction 1 said the oracle would not clear the floor. On
the diagnostic fold it clears it by tenfold — but that oracle fits **152 free parameters on the
test labels**, so a large margin is expected whether or not any structure exists. Prediction 1 as
written is therefore withdrawn as uninformative, and replaced by the comparison it should have been
in the first place:

> **1'. `blend_oracle`'s margin over `pooled` is no larger with real patterns than with random
> groups of the same sizes.** The null is the bar, not the floor. This was already prediction 4;
> it is now the primary test, and prediction 1's floor comparison is demoted to context.

Predictions 2, 3 and 4 stand as written. Withdrawal condition (a) is re-pointed at 1' — a real
margin exceeding the null margin by $\ge 0.002$ on both dev cohorts is the finding that would
matter.

**Prediction 2's stated reason is also partly wrong** and is corrected here rather than quietly:
`blend_cv`'s weakness was attributed to selection noise at small support. Part of it is the
incoherence above, which no better selection rule would fix. The prediction's direction is
unchanged; its explanation is now two causes, not one.
